# Критерии оценивания

Ниже предложена конкретизация буквенной шкалы с занятия для этого топика. Автор согласует её с преподавателем и публикует окончательную версию до выбора задания студентами. Числовые соответствия взяты с доски, распределение требований по уровням разработано для этой лабораторной.

## Уровни

| Оценка | Проверяемые условия |
|---|---|
| Э / 10 | Все условия П, вся группа expert, объяснение stale-окна, гонки PATCH/refresh и границ применимости |
| П / 9 | Все условия Б+, вся группа advanced, конкурентный эксперимент и объяснение ограничения одним процессом |
| Б+ / 8 | Все условия Б, один собственный содержательный тест нового сценария и объяснение выбранной политики восстановления и её компромисса |
| Б / 7 | Smoke и вся группа basic проходят, корректный код, заполненный базовый отчёт, воспроизводимое видео и Pull Request |
| Б− / 6 | Работают B1, B2, B3 и smoke, но есть подтверждённые недочёты в устойчивости B4–B7; они описаны в отчёте |
| У / 5 | Работают B1, B2 и smoke, но инвалидация или другие обязательные требования не завершены |
| Н / 4 | Проект запускается, есть осмысленная попытка реализации и объяснение, но cache-aside с TTL не соответствует B1/B2 |
| К / 3 | Проверяемого решения нет либо проект не удаётся воспроизвести из-за дефекта сдачи; причина зафиксирована |

Для П и Э нужен собственный тест из условия Б+. Подойдёт новый граничный случай: отсутствие фонового обновления у свежего значения, сохранность другого ключа при проблеме инвалидации, восстановление после отменённого refresh. Копия открытого теста с другим числом самостоятельным сценарием не считается.

## Как определяется итог

1. Эксперт проверяет запуск и воспроизводимость.
2. Запускает открытые проверки соответствующего уровня. В исходном наборе 22 тестовых случая, включая параметризации.
3. Смотрит код и сверяет поведение с контрактом. Прохождение тестов за счёт изменения источника или тестов не подтверждает выполнение.
4. Читает отчёт и смотрит ролик, уточняет неоднозначные результаты.
5. Выбирает самый высокий полностью подтверждённый уровень. Задания со звёздочкой не компенсируют дефекты обязательной части.

Число прошедших тестов не переводится в оценку арифметически: важен выполненный набор требований. Отдельные проверки могут проходить даже в стартовом проекте.

Недоступное видео, отсутствие инструкции и превышение четырёх минут требуют исправления сдачи. Эксперт перечисляет недостающие свидетельства и согласует исправление по правилам курса. Произвольный штраф в баллах за эти случаи здесь не установлен. До получения достаточных материалов оценка предварительная.

## Обратная связь

По каждой работе эксперт оставляет 2–3 содержательных комментария, если для них есть основания. Каждый дефект содержит шаги воспроизведения, ожидаемое и фактическое поведение, затронутый критерий и влияние на итоговый уровень. Отдельно отмечается хотя бы одна удачная практика, когда она есть.

Пример: «После прогрева ключа остановил Redis, изменил цену и восстановил Redis. GET вернул прежнее значение. Не выполнен B5, поэтому обязательная часть для Б не подтверждена. Исправьте политику восстановления. При этом блокировки разделены по ключам, что правильно сохраняет независимость товаров».

Не нужно искусственно выдумывать три недостатка у корректной работы. Не снижайте оценку повторно за несколько проявлений одного и того же дефекта.
